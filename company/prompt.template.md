# C2R company survival task

## Objective
Ship the highest-value bounded action that creates verified revenue/cash progress or the shortest necessary production proof toward it.

## Current target
Replace this section with one specific commercial target, for example:
- improve NMV/Jesus funnel conversion with an evidence-backed promotion test;
- make Zeffy browser operation pass a harmless authenticated canary;
- connect canonical campaign attribution to a real Woo test order;
- create an approval-ready reactivation campaign from verified buyer/engagement data;
- repair the lowest broken GTM layer blocking revenue.

## Required method
1. Inspect current Company OS source-of-truth issues/PRs/receipts before acting.
2. Identify the lowest broken layer: FOUNDATION, STRATEGY, EXECUTION, COMPOUNDING, or LEARNING.
3. State the economic variable this run is intended to move.
4. Use existing owned assets first.
5. Execute one bounded action that produces a real artifact, test, runtime receipt, or commercial receipt.
6. Verify it independently where possible.
7. Record actual economics; unknowns stay UNKNOWN.
8. Preserve owner gates, security, working features, rollback, and evidence.

## Anti-busywork rule
Do not spend the cycle producing another generic plan, architecture survey, tool list, or marketing brainstorm if the next executable proof is already known.

## Promotion rule
For marketing/revenue work, reverse-promote from the desired cash/customer outcome:
`outcome -> buyer state -> problem -> objection -> proof -> angle -> asset -> channel -> CTA -> destination -> follow-up -> upsell/referral -> measured result -> retained learning`

## Acceptance criteria
Define exact measurable acceptance criteria here before starting. They must distinguish BUILT/TESTED/PROVEN from merely drafted/planned.

## Receipt
At the end, report:
- STATUS: BUILT|TESTED|PROVEN|BROKEN|NOT_VERIFIED
- ECONOMIC_DELTA: verified cash/revenue/cost/owner-time facts only
- EVIDENCE: exact URLs/files/tests/receipts
- BLOCKER: only if still unresolved
- NEXT: one highest-value next action

Only output `DONE:` when every acceptance criterion is met with evidence.
